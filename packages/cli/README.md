# dsh-companion-cli

macOS Companion runtime. Requires externally installed Node.js 22+; no signed native runtime is bundled.

Use the single curl-to-bash command generated by DSH Settings → Companion Devices. The script downloads and verifies the matching CLI, then invokes `launch --server ORIGIN`; users do not manually download a CLI or choose setup versus update.

First use asks for a local SSH alias and opens browser approval. Match the terminal verification code before approving. Credentials are never argv and are stored in macOS Keychain. Existing valid pairing is verified before replacing/restarting the owned LaunchAgent; a different Host or invalid pairing requires explicit confirmation and new browser approval. Rebinding never inherits old leases. Network failure preserves existing pairing.

Internal/compatibility commands: launch, setup/install, update, daemon, status, restart, uninstall. The updater uses staged files, bounded private journals, local readiness and safe rollback. Unknown locks and unverifiable ownership fail closed. Control-channel network failures retry continuously with bounded backoff.

CLI 0.1.10 continuously retries transient Forward Instance failures (`SSH_EXITED`, start/command timeout, link loss, or missing listener) while the Lease remains valid. CLI 0.1.11 also retries local controller failures only after owned SSH cleanup completes; a fresh daemon clears legacy `LOCAL_ERROR` blocks only after startup ownership recovery. CLI 0.1.12 treats the owned SSH master process exit as listener-release proof instead of waiting for inherited stdout/stderr pipes to close. On restart it removes socket-less owner metadata only when `ps` also proves the recorded PID absent; a live, reused, or unverifiable PID remains blocked. CLI 0.1.13 retries only transient private-directory removal races (`EBUSY`, `EMFILE`, `ENFILE`, `ENOTEMPTY`, or `EPERM`) three times with short bounded delays, and persists a whitelisted `lastCleanupErrorCode` without paths or raw errors. A master that cannot be proven exited, a non-transient removal error, or exhausted cleanup retries still produces a terminal cleanup failure. Automatic retries use a maximum 30-second delay and reset the consecutive-failure counter after success. SSH authentication, Host Key, local port conflicts and unknown policy failures remain `needs_attention`; recovery never creates a Lease or extends its TTL.

SSH binds equal ports on literal 127.0.0.1. No proxy settings or user SSH configuration are modified. HTTPS is required except loopback or explicit insecure-HTTP test-network consent. Real macOS Keychain, launchd and SSH acceptance remains required.
